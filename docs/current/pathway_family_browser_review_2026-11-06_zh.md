## 4. 已确认问题明细

### PB-01：Excel 公式计数变成 0

- **位置**：CountData:496、510；287～299。
- **触发**：XLSX 拷贝数单元格使用 `=1+2`、`=SUM(...)` 或引用其他单元格的公式。
- **实际**：`cellToString()` 返回公式表达式，`parseCount()` 解析数字失败后返回 0。内存验证：公式文本为 `1+2`，最终得到 `{APC=0}`，而不是 3。
- **影响**：正常的 Excel 计算结果在通路图中成为“基因缺失”。
- **建议与验收**：读取公式计算结果或明确拒绝无法求值的公式，不可静默转零。覆盖数值公式、引用公式、公式错误；表格、角标和阶段汇总必须使用一致的值。

### PB-02：缺测值被解释为确认不存在

- **位置**：CountData:287～299；Renderer:760～765。
- **触发**：计数单元格为空、`NA` 或其他无法解析的文本。
- **实际**：这些值都被转换为 0，进入缺失基因淡化逻辑。内存验证：`Human / APC / NA` 得到 `{APC=0}`。
- **影响**：“没有数据”被展示成“确认没有该基因”，其生物学含义不同。物种为行的表格还能保留原始空值，与图形含义不一致。
- **建议与验收**：明确区分显式 0、缺测和非法值；缺测应保留未知状态或提示，非法值应定位单元格。测试 `0`、空值、`NA`、无对应基因四种情况，不能统一画成已确认缺失。

### PB-03：缓存只按基因数量区分，换表后沿用旧映射

- **位置**：Renderer:153～169；198～270。
- **触发**：同一 PPTX 配计数表 A 后，改用基因数量相同、具体基因名称不同的计数表 B。
- **实际**：缓存键只有路径、文件修改时间和基因数量；但形状分类依赖基因名称。内存验证：依次传入 `Co-receptor` 和 `PCP signalling` 两个单列基因集合，第二次返回同一个 PreparedSlide，仍保留第一次的 sprite 分类。
- **影响**：新表中的组件可能没有角标，旧组件可能继续参与淡化。重新导入也不必然修复。
- **建议与验收**：把实际影响图形分类的规范化基因集合纳入缓存身份，或将依赖计数表的分类从静态缓存中分离。至少测试“同图、相同数量、不同基因名”和“仅大小写不同”的切换。

### PB-04：PPTX 原始图层顺序被破坏

- **位置**：Renderer:320～333、399～400、752～777。
- **触发**：动态基因形状与其上层的静态箭头、说明、遮罩或其他形状相交。
- **实际**：原来的任意交错顺序被统一改为“静态骨架在下、动态形状在上”。未选物种的 fullSlideImage 也如此。
- **内存证据**：先画红色基因矩形，再画与其相交的蓝色静态矩形。POI 正常绘制重叠像素为 `0xff0000ff`（蓝）；当前分层后合成为 `0xffff0000`（红）。
- **建议与验收**：保留原绘制顺序，可按连续绘制段缓存，而不是只保留两个全局层。对比未选择物种、存在、缺失三种状态，静态连接关系不得被错误遮挡。

### PB-05：基因前缀匹配产生错误阳性

- **位置**：CountData:391～421，尤其 412。
- **触发**：图中是具体成员 `WNT1`，计数表没有 WNT1，却有 `WNT10A`。
- **实际**：双向 `startsWith` 使不同成员被认为匹配。内存验证：只有 `WNT10A=7` 时，查询 `WNT1` 返回 `OptionalInt[7]`。
- **影响**：另一个基因的计数被赋给目标基因；家族总数也可能被重复赋给多个成员。
- **建议与验收**：普通 GeneID 精确匹配，家族汇总使用显式、可辨认的映射规则。测试 WNT、WNT1、WNT10A、WNT11 共存、缺项及家族聚合，不可仅凭字符串前缀判定成员关系。

### PB-06：SVG path 等常见内容未实现，与帮助不符

- **位置**：Renderer:564～617、650～683；帮助:84。
- **触发**：导入含 `<path>` 的合法 SVG，包括许多编辑器输出的连接箭头、轮廓和基因组件。
- **实际**：图形分支只实现 rect、circle、ellipse、line，没有 path、polygon、polyline、image；也没有完整处理 transform、继承样式和 viewBox 原点。帮助却明确列出 path 可参与联动。
- **内存证据**：红色封闭矩形 path 的内部像素应为红色，当前渲染得到 `0xffffffff`（白）。
- **建议与验收**：采用完整 SVG 渲染能力并对动态映射做配套处理，或先明确拒绝未支持的元素，不能静默输出残缺图。覆盖 path、组合变换、箭头、继承样式及非零 viewBox 原点。

### PB-07：关闭标签后懒加载索引错位

- **位置**：Gallery:77、102～110、129～148。
- **触发**：导入两张以上通路图，仅第一页已加载；关闭第一页，再查看原第二页。
- **实际**：可见标签索引已经变化，但 `slidesPanel` 仍按原始顺序保存。新第 0 页会触发旧第 0 个、即已关闭面板的加载，可见图仍为空白。
- **建议与验收**：根据当前标签的实际组件获取 SlidePanel，或同步维护标签删除与列表。覆盖关闭首项、中间项、最后一项，以及全部关闭后继续点击树节点。

### PB-08：重复基因行的单基因与类别计数不一致

- **位置**：CountData:166～184。
- **触发**：基因为行的表包含两条 `APC / cat1 / 1` 与 `APC / cat1 / 2`。
- **实际**：基因 map 覆盖保留最后一行，类别 map 却累加两行。内存验证得到 `{APC=2}` 与 `{cat1=3}`。归一化后的基因列表仍包含重复列。
- **建议与验收**：明确拒绝重复 GeneID，或对各视图采用同一聚合规则；同时检查同基因跨类别的冲突。修复后单基因角标、组分表和阶段统计应能互相核对。

### PB-09：同图的基因和类别汇总被重复计入 Copies

- **位置**：Renderer:776、791、802。
- **触发**：一张图同时有 `APC_comp` 和 `cat1`，且 APC 属于 cat1，拷贝数为 3。
- **实际**：先把 APC 的 3 加入 totalCopies，再把 cat1 的同一批 3 加入，底部 Copies 显示 6。
- **建议与验收**：总计应基于定义明确、去重的数据集合，不可把同一数据的两种展示相加。分别验收“仅组件”“仅类别”“组件与类别混合”“同一基因多个图形实例”。

### PB-10：物种规范化及反向选择未统一

- **位置**：CountData:357～383；Controller:554～555、590～597。
- **场景 A**：计数表 key 是 `Homo_sapiens`，树名是 `Homo sapiens` 或 Human。只有树节点名被下划线转空格，表 key 未同样规范化，匹配失败。内存验证 `Homo_sapiens → Homo sapiens` 返回 null。
- **场景 B**：树名 Human、物种表 Name 为 Homo sapiens。树到表使用别名规则，表到树却仅 `equalsIgnoreCase`；找不到树后仍通知其他面板，导致树保持旧物种而下方面板已换物种。
- **建议与验收**：双向选择及所有数据面板共享同一名称解析结果，匹配歧义时明确反馈。覆盖空格/下划线、常用名/科学名、两个方向和“未找到节点时不产生误导性的半联动”。

### PB-11：PPTX 组合内部的命名组件未被识别

- **位置**：Renderer:198、207～270。
- **触发**：按帮助命名 `APC_comp`、`APC_name`，在 PowerPoint 中把二者组合，组合本身保留默认名称。
- **实际**：只遍历第一页的顶层形状，组内名称不参与分类。整组静态显示正常，但没有角标和淡化。若组合本身命名为 APC_comp，行为又不同。
- **建议与验收**：递归识别组内组件并考虑组合坐标变换，或明确校验并告知组合限制。覆盖一层组合、嵌套组合、组合自身命名和子组件命名。

### PB-12：【新增】旋转组件在切换物种后被截断

- **位置**：Renderer:354、373～385、1166。
- **触发**：细长动态形状（例如 APC_comp）有 45° 旋转。
- **实际**：动态层已经应用旋转，但 sprite 裁剪仍使用原始 `getAnchor()` 矩形加约 4px 边距；旋转后超出原矩形的部分丢失。初始整页图与选中物种后的图可能不同。
- **内存证据**：300×300 页面上，anchor=(100,100,120,10)、旋转 45° 的矩形，动态层有 1267 个非透明像素。按当前裁剪规则，会丢掉 997 个，约 78.7%。验证使用当前动态绘制和裁剪规则，未落盘执行完整文件导入。
- **建议与验收**：按实际变换后的绘制边界裁剪，并考虑线宽、阴影。比较 0°、45°、90°，以及存在/缺失状态，组件轮廓不得变化或缺角。

### PB-13：【新增】合法 PPTX 因没有 slide1.xml 被拒绝

- **位置**：Renderer:115～119，与 192 的真实取页逻辑不一致。
- **触发**：创建两页 PPTX 后删除原第一页，剩余物理部件为 `ppt/slides/slide2.xml`。
- **实际**：预检要求必须存在 slide1.xml，否则报告 No slides；实际第一页由 presentation 的页列表与关系决定，不由这个文件名决定。
- **内存证据**：POI 创建两页、删除第 0 页、写入内存 ZIP 后，只剩 slide2.xml；从该字节数组重新打开仍得到 1 张合法幻灯片。未将文件落盘直接调用路径校验，但当前唯一的文件名判断必然拒绝该结构。
- **建议与验收**：沿有效的 presentation 关系定位实际幻灯片。测试删除最早页、重排页面及非连续部件编号，均应加载 presentation 中的实际第一页。

### PB-14：【新增】无效 PPTX 通过预检，替换旧视图后才失败

- **位置**：Renderer:115～119；Voice:94～97；MainFace:314～319；SlidePanel:94、114～117。
- **触发**：已有正常结果，再导入一个 ZIP 中含 `ppt/slides/slide1.xml` 条目、但缺少必要 OOXML 内容或 XML 损坏的 `.pptx`。
- **实际**：快速预检只认条目存在；旧页先被 removeAll。后台真实解析才失败，仅弹出错误，不恢复原视图。此前使用 XMLSlideShow 的预检更早拦截此类错误。
- **内存证据**：将合法单页 PPTX 的 slide1.xml 内容改为 `<broken` 后，ZIP 条目仍存在，真实 XMLSlideShow 解析抛出 POIXMLException/SAXParseException。预检条件与真实解析结果存在确定差异。
- **影响**：失败导入破坏当前可用视图，不涉及原始文件被删除。视图替换的调用链由源码确认，尚未端到端运行坏文件 GUI 场景。
- **建议与验收**：在可用的新结果准备成功前保留旧视图；轻量预检不能替代提交前的真实解析。覆盖损坏 XML、缺关系、缺内容类型、解析和渲染失败，并断言旧树、分析页、选择及布局仍可使用。

### PB-15：【新增】计数合法性未检查，数值被静默改写

- **位置**：CountData:296；类别累计还经过 182。
- **实际实现**：`(int) Math.round(Double.parseDouble(trimmed))`，没有有限性、非负、整数和范围校验。
- **本轮内存结果**：

| 输入 | 内部计数 |
| --- | ---: |
| `-1` | -1 |
| `1.5` | 2 |
| `NaN` | 0 |
| `Infinity` | -1 |
| `2147483648` | -2147483648 |

- **影响**：非整数被擅自取整；超范围值截断，负数继续参与类别累计。非法输入可能被画成缺失，或使汇总异常。
- **建议与验收**：按拷贝数域校验有限、非负、范围内整数；禁止静默改写，累计也应检查溢出。测试上表以及合法的 0、1、较大整数，并给出出错行列。

### PB-16：【新增】类别大小写混用导致漏统计

- **位置**：CountData:171～184；Renderer:812～814。
- **触发**：两条记录分别为 `APC / cat1 / 2`、`AXIN / CAT1 / 3`。
- **实际**：解析按原始大小写生成不同 key，绘图却忽略大小写查找并返回第一项。内存验证：类别 map 为 `{cat1=2, CAT1=3}`，cat1 槽位取到 2，而不是 5。
- **建议与验收**：类别名称在解析和匹配时采用同一规范化策略，或明确拒绝等价名称冲突。测试 cat1/CAT1 混用以及输入顺序颠倒，汇总结果不应随顺序变化。

## 5. 待验证项与证据修正

### V-01：TXT 导出空回调风险——修正上次结论的证据等级

### V-02：全局图片缓存无回收策略

- **位置**：Renderer:50、153～169。
- 静态 SLIDE_CACHE 无容量限制和清理路径；修改 PPTX 的 mtime 会产生新 key，旧整页图和 sprite 仍被引用。

- **待办**：重复打开/修改大型文件并测量关闭模块后的堆占用，确认实际增长，再决定容量、生命周期或淘汰策略。已确认无界保留的结构，未做长期内存压力测试。
